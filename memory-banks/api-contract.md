# API Contract

Shared interface between frontend and backend. **Both agents must read this file before starting work.**

When either agent needs a change that crosses the boundary, add it to [Pending Changes](#pending-changes) below.

---

## POST `/api/taste-profile`

**Request:**
```json
{ "description": "string — free-text description of the recipient" }
```

**Response:**
```json
{
  "tasteProfile": {
    "recipient": { "name": "string|null", "relationship": "string|null" },
    "occasion": "string|null",
    "budget": { "min": "number|null", "max": "number|null" },
    "interests": ["string"],
    "interestAliases": { "interest": ["shopping tokens"] },
    "aesthetic": "string|null",
    "personality": "string|null",
    "constraints": ["string"],
    "giftingContext": "string|null",
    "summary": "string|null",
    "clarification": {
      "question": "string",
      "options": [{ "label": "string", "patch": {} }]
    }
  }
}
```
- `clarification` is `null` when the description is detailed enough.

## POST `/api/recommendations`

**Request:**
```json
{
  "tasteProfile": { "...pre-built taste profile object" },
  "description": "string (optional fallback)"
}
```

**Response:**
```json
{
  "recommendations": [ "...Recommendation objects (see schema below)" ],
  "meta": {
    "curatedFor": "string — recipient name or relationship for heading",
    "summary": "string — rich text summary (supports **bold** markers)"
  },
  "tasteProfile": { "...echo back" }
}
```

## Recommendation Object Schema

This is the contract. Every field listed here must be provided by the backend. The frontend renders based on these fields.

```js
{
  // ── Currently populated by backend ──
  name:              String,    // Product name
  price:             String,    // Display price (e.g., "$49.99")
  description:       String,    // Product description (from enrichment, "" if unavailable)
  brand:             String|null,
  rating:            String|null, // e.g., "4.7" — prefers merchant-level, falls back to Google aggregate
  tag:               String,    // Category label — "TOP PICK" or "GREAT FIND"
  ctaText:           String,    // Button text — "View Product"
  ctaColor:          String,    // Hex color for CTA — "#c8956c"
  url:               String,    // Purchase link (merchant URL or Google Shopping fallback)
  imageUrl:          String,    // Primary product image
  imageUrls:         String[],  // Thumbnail gallery (empty array if <= 1 image)
  imageBg:           String,    // Fallback background color — "#252220"
  matchedAttributes: [{ label: String, category: String }], // LLM-generated gift-fit pills (1-2 per product)
  merchantBadges:    String[],  // e.g., ["Free Shipping", "30-Day Returns"]

  // ── NOT YET populated by backend (frontend expects these) ──
  matchScore:        Number|null,   // 0-100 match confidence score. Frontend shows MatchRing when >= 85.
  badgeLabel:        String|null,   // e.g., "Best Match", "She'll Love This", "Perfect for the Occasion"
  badgeType:         String|null,   // One of: "confidence", "social", "occasion" — drives icon + color
  reactionLine:      String|null,   // Predicted recipient reaction, e.g., "She'll use this every morning"
}
```

### Field details for missing fields

**`matchScore`** (Number, 0-100)
A confidence score for how well this product matches the taste profile. Used by `MatchRing` component — only renders when score >= 85. Could be derived from the existing prune scoring weights or a dedicated LLM call.

**`badgeLabel`** + **`badgeType`** (String, String)
Replaces the generic `tag` field ("TOP PICK"/"GREAT FIND") with a richer badge system. Types:
- `"confidence"` — high match score (sparkle icon, copper text)
- `"social"` — social/emotional fit (heart icon, warm-gray text)
- `"occasion"` — occasion-specific fit (gift icon, sage text)

When `badgeLabel` and `badgeType` are both present, the frontend shows the badge instead of `tag`. When absent, falls back to `tag`.

**`reactionLine`** (String)
A short, italicized predicted reaction quote displayed below the product name. E.g., *"She'll use this every morning"* or *"This is so her style."* Likely generated by LLM alongside pill labels.
